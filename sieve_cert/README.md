# Sieve certificate

An independent re-check of the Mordell–Weil sieve (PROOF.md §C.3, Proposition 6.2 of the paper) for
both curves of the hard pair, B⁻: y² = −C₃(x) and C⁺: y² = 2C₃(x), at the main prime p = 499 and in
the independent rerun at p = 1459. The original sieves are `step4_sieve.gp`, `twist/step4_sieve.gp`
and the copies built by `second_prime/make_p1459.py`, run in PARI/GP. Here the same conclusions are
reached from a small set of exact inputs, by code that shares nothing with PARI.

## What the sieve claims

The quadratic Chabauty step leaves 524 candidates on B⁻(ℚ₄₉₉) and 504 on C⁺(ℚ₄₉₉), each with a
coefficient vector a(z) ∈ ℤ₄₉₉² with respect to the generators: P₁ = (1, 1), P₂ = (−1, 15) on B⁻,
and P₁ = (6/5, 172/125), P₂ = (2, 12) on C⁺. On each curve the sieve removes every candidate except
the four known points, using the same two primes of L:

| | B⁻ | C⁺ |
|---|---|---|
| prime above q = 997 (t ↦ 35) removes | 518 | 494 |
| prime above q = 12973 (t ↦ 775) removes | 2 | 6 |
| survivors | 4 | 4 |

The other 22 primes in the step-4 logs remove nothing, so the certificates use only these two.

**The rerun at p = 1459.** Here the candidates live in ℤ₁₄₅₉², and the sieve works in the
1459-parts of E₁(𝔽_q), E₂(𝔽_q) at the primes of L above 2917 and 26261:

| p = 1459 | B⁻ | C⁺ |
|---|---|---|
| candidates | 1546 | 1426 |
| prime above q = 2917 (t ↦ 1166) removes | 1538 | 1422 |
| prime above q = 26261 (t ↦ 1439) removes | 4 | 0 |
| survivors | 4 | 4 |

The original rerun kept only the candidate counts, not the lists. The lists were regenerated by
rerunning its residue-disk step (`step3_run.gp` from `make_p1459.py`). The regenerated summaries
(disks, Strassmann indices, zeros, rational-looking points) are identical to the recorded
`logs/p1459/*/step3_aggregate.out`. The lists are now kept in `logs/p1459/*/step3_candidates.gp`.

On C⁺ the two disks x ≡ 103 gave coefficient vectors of zero precision in the main run. As in the
record (RESULTS.md, p = 1459), they are replaced by the four vectors recomputed at higher precision
in `second_prime/cands103_Cplus.gp`; `emit.gp` does the replacement and reports it. The 1422
removed at 2917 are PARI's 1418 plus these four, which the record's follow-up sieve
(`logs/p1459/Cplus/sieve103.out`) also removes at 2917.

## The files

| file | what it does |
|---|---|
| `emit.gp` | Exports the exact inputs from PARI, for each curve and each run: the prime ℓ = p, the sextic f, the generators P₁, P₂, the field L, the fixed points x± of the involution as elements of L, the sieving primes, and the candidate vectors mod ℓ. It runs in a few seconds. |
| `inputs_Bminus.txt`, `inputs_Cplus.txt`, `inputs_Bminus_p1459.txt`, `inputs_Cplus_p1459.txt` | Those inputs, as text. |
| `check.py` | An independent checker in plain Python, with no PARI and no libraries. It runs in about 7 seconds. |
| `emit_lean.py` | Writes `lean/Fermat433/Sieve/Data*.lean`, one per run: the inputs plus a removal witness for each removed candidate (see below). |
| `../lean/Fermat433/Sieve/Check.lean` | The Lean checker. |
| `../lean/Fermat433/Sieve/Theorem.lean`, `TheoremP1459.lean` | The theorems `sieve_B_minus`, `sieve_C_plus`, `sieve_B_minus_p1459`, `sieve_C_plus_p1459`, proved by evaluating the checker in Lean's kernel, plus tests that spoiled witnesses are rejected. |

Both checkers start from the input files and recompute everything else themselves:
- they reduce L at the prime and build the quotients E₁, E₂;
- they count E₁(𝔽_q) and E₂(𝔽_q) by brute force, and check that the ℓ-parts are cyclic of order ℓ
  (ℓ = p = 499, or 1459 in the rerun);
- they compute the images of the generators and each candidate's target (T₁, T₂).

Neither uses PARI's generators, discrete logarithms or allowed sets. The sieve's verdict does not
depend on those choices, so this is a genuine second computation, not a replay. The two checkers
also differ from each other in how they decide that a candidate is removed:

- **`check.py` works forwards**, like PARI. It enumerates all of X(𝔽_q), maps every point to the
  ℓ-parts, and removes a candidate whose target is not among the images.
- **The Lean checker works backwards**, from a witness. Multiplication by c₁ = #E₁(𝔽_q)/ℓ maps
  E₁(𝔽_q) onto its ℓ-part, and every fibre has exactly c₁ points. A list of c₁ distinct points Q
  with c₁·Q = T₁ is therefore the whole fibre over T₁. Each Q comes from at most two points of X:
  in the even model Y² = AX⁶ + BX⁴ + CX² + D they are (±√(u/A), v/A). The candidate is removed if
  none of those points is sent to T₂ on E₂.

  The certificate supplies each fibre and the square roots, and the checker verifies all of them.
  That is about 50 points per removed candidate at q = 12973, instead of all 12,974 points of
  X(𝔽_q). Without it the kernel check does not finish.

## Result

All three implementations agree exactly, on both curves and at both primes:

| | PARI | Python (`check.py`) | Lean kernel |
|---|---|---|---|
| B⁻, q = 997: removed, left | 518, 6 | 518, 6 | 518, 6 |
| B⁻, q = 12973: removed, left | 2, 4 | 2, 4 | 2, 4 |
| C⁺, q = 997: removed, left | 494, 10 | 494, 10 | 494, 10 |
| C⁺, q = 12973: removed, left | 6, 4 | 6, 4 | 6, 4 |
| survivors, a mod 499 | (±1, 0), (0, ±1) | same | same |
| B⁻ at p = 1459, q = 2917 / 26261: removed | 1538 / 4 | 1538 / 4 | 1538 / 4 |
| C⁺ at p = 1459, q = 2917 / 26261: removed | 1418 + 4 / 0 | 1422 / 0 | 1422 / 0 |
| survivors at p = 1459, a mod 1459 | (±1, 0), (0, ±1) | same | same |

The Lean results are theorems checked by the kernel:

```lean
theorem sieve_B_minus : run Bminus.inputs Bminus.certs = some [(1, 0), (498, 0), (0, 1), (0, 498)]
theorem sieve_C_plus : run Cplus.inputs Cplus.certs = some [(0, 1), (0, 498), (1, 0), (498, 0)]
theorem sieve_B_minus_p1459 : run Bminus_p1459.inputs Bminus_p1459.certs =
  some [(1, 0), (1458, 0), (0, 1), (0, 1458)]
theorem sieve_C_plus_p1459 : run Cplus_p1459.inputs Cplus_p1459.certs =
  some [(0, 1), (0, 1458), (1458, 0), (1, 0)]
```

All four depend only on the axiom `propext`; in particular they do not use `native_decide`, so
Lean's compiler is not trusted. CI rebuilds them and checks the axioms on every change.
`Theorem.lean` also spoils B⁻ witnesses in six ways (a missing fibre point, a repeated one, one
repeated in unreduced form, a wrong square root, a point off the curve, a wrong prime of L) and
checks that each is rejected.

The two at p = 499 take about 30 seconds together. The two at p = 1459 take about 65 seconds and
7.6 GB of memory. Two choices in the checker keep them within reach of the kernel: Euler's
criterion uses the kernel's built-in exponentiation, `a ^ ((q − 1)/2) % q`, rather than a
square-and-multiply loop; and the removal witnesses are matched to the candidates in one pass,
rather than by searching the list of witnesses for each candidate.

The survivors are the four known points P₁, ιP₁, P₂, ιP₂. That they survive is also a consistency
check on the exported conventions: if x₊ and x₋ were swapped, or the generators mismatched, the
known points would be removed too.

## What this establishes

**Established:** given the candidate vectors, the finite arithmetic of the sieve is right. The
reductions, group orders, cyclicity of the ℓ-parts and the sieving condition were all recomputed
without PARI, and the Lean computation is proved sound (below).

**The soundness proof.** The four kernel theorems say that a program returns the four survivors.
`sieve_B_minus_sound`, `sieve_C_plus_sound`, `sieve_B_minus_p1459_sound` and
`sieve_C_plus_p1459_sound` (in `lean/Fermat433/Sieve/Sound/Main.lean`, all instances of
`run_sound`) turn that into mathematics. For each removed candidate a = (a₁, a₂), there is a
sieving prime q at which no point P of X(𝔽_q) satisfies both

  c₁·φ₁(P) = a₁·c₁·φ₁(P₁) + a₂·c₁·φ₁(P₂) on E₁  and  c₂·φ₂(P) = a₁·c₂·φ₂(P₁) + a₂·c₂·φ₂(P₂) on E₂,

where P₁, P₂ are the curve's generators and cᵢ = #Eᵢ(𝔽_q)/ℓ, with ℓ = p = 499 or 1459. The
curves Eᵢ, their points and group law are Mathlib's (`WeierstrassCurve.Affine.Point` over
`ZMod q`). The maps φᵢ are given by their formulas: the change of variable X = (x − x₊)/(x − x₋),
Y = y(X − 1)³ to the even model, then (AX², AY) and (D/X², DY/X³). X(𝔽_q) includes the points at infinity and the special points
x = x±. These theorems depend only on Lean's three standard axioms.

The proof is in four layers in `lean/Fermat433/Sieve/Sound/`:

| layer | statement | status |
|---|---|---|
| 1. arithmetic (`Arith.lean`) | `powMod`, `inv`, `sub`, `ofInt` compute exponentiation, inverses, subtraction and casts in `ZMod q`; `euler` returning `q − 1` means "not a square" | proved |
| 2. group law (`Curve.lean`) | `Curve.add` and `Curve.mul` are Mathlib's addition and `n • ·`; points passing `onCurve` are points; `disc ≠ 0` gives `Δ ≠ 0` | proved |
| 3. counting (`Count.lean`, `Fibre.lean`) | `Curve.order` is the number of points (`card_eq_order`); in a group of order `ℓc` with `ℓ` prime and `ℓ ∤ c`, `c` distinct points of a fibre of `c • ·` are the whole fibre (`mem_of_fibre`) | proved |
| 4. the sieve (`Poly.lean`, `Geometry.lean`, `Bridge.lean`, `Sieve.lean`, `Main.lean`) | the list polynomials compute `F`; points of `X` land on the even model and on `E₁`, `E₂`; the checker's `phi` and fibre test are correct; `sievePrime` returning `some` implies the statement above | proved |

Writing layer 4 exposed one real gap in the checker, now closed. Fibre points were not required to
be reduced mod q, so a certificate could have listed (x, y) and (x + q, y) as two "distinct" points.
The checker now rejects this, and `Theorem.lean` tests that it does. A few other facts the proof
needs (f has seven coefficients, F at most seven, A = f(x₋), D = f(x₊), values reduced mod q,
ℓ < q, q > 15) are also checked at run time rather than derived.

## What is not established

- That the candidate vectors are the zeros of the quadratic Chabauty function (§6,
  Proposition 6.1). The certificate takes them as given.
- That the sieve condition above is the right one, i.e. that a rational point's coefficient vector
  must satisfy it (Proposition 6.2). This links φᵢ over 𝔽_q to the maps over L and to J(ℚ).

## Reproducing

From the repository root:

    gp -q sieve_cert/emit.gp          # rewrites inputs_*.txt (needs PARI/GP 2.17)
    python3 sieve_cert/check.py       # all four runs, about 7 seconds
    python3 sieve_cert/emit_lean.py   # rewrites lean/Fermat433/Sieve/Data*.lean (about 10 seconds)
    cd lean && lake build             # includes the kernel checks of all four sieves
